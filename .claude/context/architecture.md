# Architecture

How the code is put together, for an agent about to change it. User-facing behaviour is in `README.md` and `docs/`; this file holds what those leave out. Line numbers are from `master` at ec45a5b (2026-10-07) and drift: search for the method name.

## Map

|---|---|---|

## A call, end to end (`VoiceSession`)

1. `start()` (~:462): reads `OptOuts::all()` first and throws when it cannot (the command then refuses to record), reads `GuildSettings`, makes `RECORDINGS_PATH/<guild>/<Y-m-d_H-i-s>/`, constructs (`player()` picks the `Player` from `VOICE_PLAYER`), then `listen()`, `wait()` (pre-starts a Claude Code process), `speech->start()` (starts Piper, and the ffmpeg that waits for the first sentence), `transcriber->server?->acquire()` (starts or joins the whisper server), logs `Voice session started`, warns about a bad `VOICE_PAUSE_SECONDS` or `VOICE_PLAYER`, registers in `$unfinished` and `$sessions`. `RecordsCalls` refuses before this while `refusesNewCalls()`, and closes a client that joined after it turned true.
2. `listen()` (~:850): `vc->record(WAV, cb)`; the callback runs on a speaker's first audio and returns their WAV path, or `/dev/null` for an opted-out or unnamed speaker. A `pcm` listener feeds `UtteranceSplitter::push()` and `hear()`. A 50 ms ticker calls `flushSilent()`. Both are wrapped by `guarded()` (~:920). `vc->once('close', stop)`.
3. `UtteranceSplitter`: one WAV per utterance; an utterance ends after `VOICE_PAUSE_SECONDS` of silence (default `UtteranceSplitter::SILENCE_SECONDS` 0.6, minimum 0.1, an invalid value warns and uses the default), is dropped under `MIN_SECONDS` 0.5, and is cut at private `MAX_SECONDS` 30. Its callback is `queueUtterance()`.
4. `queueUtterance()` (~:945): captures `$people = group($user)` **at speech time**, records the clip in `$clips`, logs `Utterance ended`, tracks `UTTERANCE`, and puts `handleUtterance()` on the queue with `inTurn()`.
5. `handleUtterance()` (~:1038): skips when the clip was dropped (opt-out); transcribes with the clip's length in seconds (a transcription failure becomes `FailedReply(WHISPER)`); logs `Transcribed`; returns on empty text or an opted-out speaker; writes the transcript line with `remember()` **before the answering decisions**; then checks in this order: session stopped, leave phrase (`leave()`: `sayOkay()`, posts `<name> ended the call by voice.`, then `stop()`), stop phrase (`Not answering`, reason `the stop phrase`: never sent to Claude, nothing said back), a sentence that only calls the bot (`onlyCalls()`: the wake word and at most `CALLING_WORDS` 1 other word; sets `$called[user]`, reason `only the wake word`), no wake word and not called within `CALLED_SECONDS` 5 (`Claude was not addressed`), else `answer()`. The order matters because the default stop and leave phrases contain the wake word. **There are no conversations since PR #44**: a sentence is answered when it names the bot, or when it is the first thing that person says within 5 s (speech time, `hrtime`, taken in `queueUtterance()`) of a sentence that only called it.
6. `answer()` (~:1216): builds the prompt (`prompt()`: memories, then `conversation()`, the whole call so far cut by `Lookups::recent()`, then `Lookups::asking($name, $said)`, which names the transcript entry being answered), asks Claude through `ask()` (~:1440, logs `Asked Claude` with `lines` and `characters`; streaming; `Claude started answering` comes from the `$onStarted` callback), pushes text through `HandOff` (hides the `LOOK UP:` line) into `SentenceSplitter` (with `VOICE_FIRST_WORDS`, the first words of the answer come out before their sentence is whole, and the rest of that sentence when it ends, however short; not for an answer that is held back), gives each sentence to Piper as soon as Piper has written the one before it (`$free` chain, on `Sentence::voiced()`) and plays it through `$player->play($sentence, $onStart)` once the player is ready for it (`Player::ready()`: the bot's own from the sentence's first packet, the library once its file is whole) and the ones before it are over; `stillAnswering()` is checked between the two, so nothing can change between the check and the call hearing it (`$spoken` chain: one sentence at a time, in order). `Started speaking` is the first play's `$onStart`. Each play is `race([player->play, $left, $speaking['cut']])`. A sentence that was given to Piper and is not played is in `$unplayed` until the answer is over, and is then dropped (`Sentence::drop()`: no `claude-N.ogg`). On the whole answer: logs `Claude answered`, runs the privacy checks again, posts to the text channel, remembers, tracks `ANSWERED`, hands off a lookup when there is a task. When `Lookups::full()`, nothing is spoken until the answer is whole and `Lookups::BUSY` replaces a hand-off. When Claude fails: posts `Sorry, I couldn't get an answer from Claude. (<msg>)`, lets the sentences already finished be spoken, then throws `FailedReply(CLAUDE)`, so `inTurn()` logs `Voice reply failed` and tracks `FAILED`. `hear()` (~:1371) cuts an answer the asker talks over.
7. `stop()` (~:702): idempotent. Sets `$stopped`, cancels the ticker, stops the waiting Claude, Piper and the waiting ffmpeg, flushes the splitter (the last utterance is still transcribed for the transcript, not answered), stops recording, resolves `$left` (cuts playback), calls `$player->stop()`, closes the voice client, logs `Voice session stopped`, tracks `CALL_ENDED`. Then chains `summarize()` (a failure posts `Sorry, I couldn't summarize the call. (...)`) → `updateMemories()` → wait for Piper and for the ffmpegs still encoding → in `finally`, remove from `$unfinished` once `$allLookedUp` settles and `transcriber->server?->release()` (the last call to release ends the server). `deleteDecoderFiles($ssrcs)` removes the voice library's temp copies; `Application`'s `init` listener calls it without arguments at start-up for what a crashed run left, and starts `Retention` (hourly deletion when `RECORDINGS_RETENTION_DAYS` is set).

Callers of `stop()`: `/stop`, the voice client's `close` event, `leave()`, `Meeting::end()`, `Meeting::recordedBy()` when the meeting ended while the bot was joining, `Application::stop()` (signals). `abandon()` (~:788) posts `VoiceSession::LEFT` to the text channel, then `stop()`; callers: `Application::stop()` with a non-zero exit code and `guarded()` after `BROKEN` 3 failures.

## `VoiceSession` state (private fields)

- `$queue`: tail of the serial promise chain; `$allLookedUp`: chain of lookups, never rejects; `$lookingUp[id] = [promise, $stillWanted]`: lookups that can still be stopped (`dropUnwantedLookups()`); `$left`: Deferred resolved in `stop()`.
- `$transcript[n]`: **the whole call**, one entry for each thing said, with its time, exactly as in `transcript.txt`, keyed by the number it was added as (`$entries` is the last number). Questions, the telling of a lookup and lookups take it from here, in the same synchronous step as their privacy checks (no file read); `summarize()`, the memory updates and `/recall` still read the file. `/forget` takes the entries the forgotten memory's owner said alone (`$said[$key]`, keyed by the same numbers) out of it by number, never by text, and rewrites the file from it (`removeFromTranscript()`; the file is deleted when nothing is left): lines said with others there, and Claude's answers, stay, and are part of every later question.
- `$clips[wavPath] = userId`: utterances waiting for transcription; opt-out unlinks them. `$audio[user]`: WAVs to delete on opt-out. `$files`: one counter shared by `<user>-N.wav` and `claude-N.ogg`.
- `$called[user] = float`: who only called the bot with the last thing they said, and when that sentence ended (`hrtime` seconds). Read and unset by that person's next sentence in `handleUtterance()`, unset by `optOut()`. `$conversations`, `$waiting`, `openConversation()`, `closeConversation()`, `startQuiet()`, `CONVERSATION_QUIET`, `CONTEXT_LINES` and `UtteranceSplitter::isSpeaking()` are gone (PR #44). `$turns` (int) is what is left of `$waiting`: how many turns wait or run, counted up in `inTurn()` and down in its `->finally()`, read by `saveUsage()` (PR #36) to write the statistics only when no call is answering.
- `$speaking = {user, since, heard, heardAt, interrupted, cut: Deferred} | null`: exists from the first played sentence to the end of the answer.
- `$player` (readonly, constructor): the `Player`. `$waitingClaude`: the pre-started `WaitingClaude`, or null. `$pauseSeconds`: `VOICE_PAUSE_SECONDS` or the default. `$firstWords`: `VOICE_FIRST_WORDS`, 0 when it isn't set or isn't a whole number.
- `$counts = {utterances, answers, failures}`: logged in `Voice session stopped`. `$apologized[step]`: steps the call was already told "Sorry, something went wrong." for, so each step is said once per call.
- `$said[key]`, `$forgotten[key]`: lines per memory key (`implode('-', sorted ids)`) and a counter bumped by `forget()` so in-flight work can tell "forgotten since I started".
- `$shared[user]`: insertion-ordered; `sharers()` is the last `SHARED_MEMORIES` 5 minus the asker.
- `$optedOut`: mutable map kept in sync by the static `optOut()`/`optIn()`.
- Statics: `$sessions` by guild (active), `$unfinished` by id (until summary, memories and lookups are done; `Retention` skips those folders), `$starting` (join race guard), `$refusing` (set by `refuseNewCalls()` when the bot is stopping; never reset).

## The one-turn queue

`inTurn($userId, $turn)` (~:972): `$turns++`, then `$queue = $queue->then($turn)->catch(log 'Voice reply failed' with `step`, count, track FAILED, return `apologize()`)->finally($turns--, saveUsage())`. `apologize()` (~:1003) posts per step and says `SORRY` aloud once per step.

- A turn returns a promise that settles when the bot has finished speaking, or `null`. **Never `stop()`'s promise**: `stop()` continues `$queue`, which holds the turn. `leave()` calls `stop()` and returns something else on purpose.
- Promises in ReactPHP v3 run their handlers synchronously when already settled. `$left->resolve()` inside `stop()` runs handlers before the queue tail attaches. A `cancel()` right after registering on an idle queue is a no-op.
- `post()`, `sayOkay()` and `apologize()` never reject. `say()` can (it throws `FailedReply(SPEECH)` on a Piper, ffmpeg or player failure); its caller runs inside `inTurn()`, which logs it as `Voice reply failed`.

## Privacy seams (where state is re-read)

| Moment | Check | Where |
|---|---|---|
| Utterance ends | speaker opted out → clip deleted | `queueUtterance`, `optOut()` |
| Before transcribing | clip still in `$clips` | `handleUtterance` |
| After transcribing | opted out, `unlessOptedOut($people)` | `handleUtterance` |
| Building the prompt | the whole transcript is taken from memory in this step (`conversation()`), with no wait between it and the checks; `personalMemoryBasis()`: `ASKED` (user setting `when_asked`, also the default with no row), `SHARED`, `ALONE`, or none; `/privacy` is read fresh every question, and a failed read (`find()` null) falls through to the strict choices | `answer()` decides the basis, `prompt()` reads the memories |
| Before each sentence is given to Piper, and again before it is played | `stillAnswering()` = not stopped, not opted out, not interrupted, `stillSharing`, `stillAlone`, `stillAmong` | sentence callback in `answer()` |
| After the whole answer | the same four, each logging `Not answering` and skipping post/remember/track | `answer()` |
| Memory update | `forgotten[key]` unchanged and nobody opted out | `updateMemory()` save guard, `MemoryWriter::$stillWanted` (checked before and after Claude) |
| Lookup result | `$wanted()`: `$stillWanted` (not opted out, still sharing, no memory it read forgotten since) and still among the same people (or what held when the call stopped); the telling is gated on it too | `lookUp()`, `lookedUp()` |
| Lookup running or waiting | `$stillWanted` alone (permanent reasons only: someone joining and leaving again stops nothing) → the lookup is cancelled (`Stopped looking something up`), nothing is posted, told or remembered | `dropUnwantedLookups()`, called from `optOut()`, `unshareEverywhere()`, `forget()` and once after a lookup is registered |

`group($speaker)` returns `null` (no group memory) when the bot is not in the cached voice states, only bots are there, more than `MemoryGroup::MAX_PEOPLE` 5 people, or anyone there opted out. Someone leaving is fine; someone joining cuts an answer made from a group memory (`stillAmong`).

## Claude Code and Piper as processes

- `Claude::command()` (`app/Voice/Claude.php` ~:145): `claude --print --output-format stream-json --verbose --include-partial-messages --model M [--advisor A] --system-prompt P --tools '' --strict-mcp-config --no-session-persistence --setting-sources ''`, cwd `sys_get_temp_dir()/discord-bot-claude` (empty, 0700). Lookups use `--tools WebSearch --allowedTools WebSearch`. The prompt goes on stdin.
- Environment (`environment()` ~:178): inherits `getenv()` minus `ANTHROPIC_API_KEY`; sets `DISABLE_AUTOUPDATER=1` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (unset again for lookups: with it Claude Code offers no advisor); `MAX_THINKING_TOKENS=0` for call answers (`thinks: false`), inherited for everything else.
- `WaitingClaude`: a process started with `--input-format stream-json` before the question exists; the prompt is one JSON line `{"type":"user","message":{"role":"user","content":...}}`, stdin closed, 120 s timeout. `wait()` replaces it when it ends after living ≥ `WAITING_SECONDS` 2 s (no respawn loop). `waitedMs()` is how long it had run when asked (the `Asked Claude` log). `ask()` falls back to a cold process and logs a warning.
- `ClaudeAnswer`: reads `stream_event` `text_delta` and `result`, and counts `system` `init` (time), `api_retry` and non-`allowed` `rate_limit_event` for `timing()`, which goes to `$onStarted` just before the first piece. Times use `hrtime`. Rethrows `RuntimeException('Claude Code: ...')` only when `is_error` is true; answers are never quoted in errors.
- `HandOff::MARKER = 'LOOK UP:'`: must be the last non-blank line, at column 0; `push()` holds a trailing line while it could still be the marker; `flush()` is required at the end of the stream.
- `Speech` (Piper): one long-running `piper --model M --output-dir <call>/piper`, one sentence per stdin line; sentence N resolves FIFO on a stderr line matching `/^INFO:__main__:Wrote (.+)$/`. `synthesize($text, $oggPath)` returns a `Sentence` at once. At `Wrote` the WAV is read and deleted, and its bytes go to the stdin of an `Encoder`: an ffmpeg started ahead with `-probesize 32 -analyzeduration 0 -f wav -i pipe:0 -af Speech::TRIM -c:a libopus -page_duration 20000 -flush_packets 1 -f ogg pipe:1` (default 20 ms frames: `OggPlayer` sends one packet per 20 ms, and `VoiceCallTest` counts packets; a page per packet, written at once). One always waits (`$waiting`, `isReadyToEncode()`): `start()` starts the first, `encode()` the next when a sentence takes it, `prepare()` another when it had stopped by itself (`VoiceSession::synthesize()` then warns `ffmpeg had stopped: starting it again`). Starting an ffmpeg is 60 to 100 ms; started ahead, the first packet is there 5 to 14 ms after `Wrote`. One ffmpeg kept for the whole call was measured 5 to 13 ms faster and not built: `TRIM` needs the end of the audio. `stop()` ends the one that waits and resolves once Piper and the ffmpegs still encoding have ended.
- `Sentence`: a sentence on its way to the call. `voiced()` (Piper wrote it: Piper is free), `started()` (the first bytes of its Ogg stream came: it can be played), `whole()` (the ffmpeg ended: `claude-N.ogg` is written, in one `file_put_contents`). `write()`, `end()` and `fail()` are the encoder's side; `packets()` (read by an `OggOpus` it owns, only when asked: the feature tests' streams are no Ogg), `isOver()`, `failure()` and `watch()` the player's; `drop()` for a sentence nobody will hear (the file is not written, or deleted). `TRIM` takes the silence off both ends (`silenceremove` at -60 dB, 20 ms kept before the first sound and 50 ms after the last; the end by `areverse`, so pauses inside the sentence stay; `apad` makes it at least 40 ms so a silent sentence still has packets). It applies to every voice: Piper's start goes from about 56 to 15 ms and its end from about 200 to 50 ms. At -45 dB it cut the soft start of an "s", "h" or "f" and the soft end of a "v" (audio up to -36 dB), so do not raise the threshold; `SpeechTrimTest` fails for -45 dB. A started sentence cannot be taken back. Per-sentence timeout 120 s kills Piper, and the same 120 s the sentence's ffmpeg; `VoiceSession::synthesize` restarts it with the warning `Piper had stopped: starting it again`.
- **Kokoro** (`kokoro/`, Python, PR #38): `PIPER_BINARY=<repo>/kokoro/kokoro` (a launcher for `kokoro/venv/bin/python kokoro_serve.py`), `PIPER_MODEL=<repo>/kokoro/voices/af_heart.onnx`. `Speech` starts it exactly as it starts Piper (`--model <file> --output-dir <folder>`, one sentence a line, `INFO:__main__:Wrote <path>` on stderr, ends when stdin closes). `kokoro_serve.py` is the protocol (WAV 24 kHz mono 16-bit named `<n>.wav`, 0.1 s of silence for an empty or unspeakable line so one line in is always one `Wrote` out, `DEVICE cuda (<card>)`/`DEVICE cpu` first, `READY {json}` once warm, `FIRST <ms> AUDIO <s>` before each `Wrote`; `TTS_QUIET` drops READY and FIRST; model read from `kokoro/hf` offline); `engine.py` is the only file that imports torch, kokoro and numpy (`KOKORO_ENGINE` names another module: `tests/Fixtures/kokoro/stand_in_engine.py`). `--model` is only a name: `install.sh` makes an empty `voices/<name>.onnx` per voice so `Speech::voices()` and `missingSetup()` need no change. Installed by `kokoro/install.sh` into `kokoro/venv`, `hf`, `voices` (git-ignored).
- `Player` (`app/Voice/Player.php`): `ready(Sentence $sentence): PromiseInterface` (when the player could start on it: `started()` for `OggPlayer`, `whole()` for `LibraryPlayer`; `answer()`, `say()` and `sayOkay()` wait for it before they look whether the sentence is still wanted), `play(Sentence $sentence, ?$onStart): PromiseInterface` (resolves when the sentence was sent, rejects when it can't be played or its encoder failed; `$onStart` runs at its first packet) and `stop()` (cuts the sentence, drops the queue). `VoiceSession::player()` picks `OggPlayer` (`VOICE_PLAYER` unset or `bot`) or `LibraryPlayer` (`library`); anything else warns and plays as `bot`. `OggPlayer`: reads `Sentence::packets()` at every tick, so a sentence is played while the rest of it still comes; when the next packet isn't there at its turn no timer is armed (`$starved`), and `came()` (the sentence's `watch()`) sends it when it comes and starts the pace over from there, without a burst; `begin()` sets speaking on and the first packet goes out `HEAD_START` 0.04 s later; one packet per `FRAME` 0.02 s from a timer paced by `hrtime` (a packet over `LATE` 0.1 s behind restarts the pace instead of bursting); a file given while another plays follows it in the same stream; after the last file `SILENCE_FRAMES` 5 `UDP::SILENCE_FRAME` frames go out, then speaking is set off, and a file given meanwhile continues the stream; `stop()` sends the 5 frames at once and resolves what waited with null. `LibraryPlayer` waits for `Sentence::whole()`, calls `$onStart` and hands the file to `vc->playFile()` (not when it was stopped meanwhile: `$stops`), which starts an ffmpeg and sends its first packet 0.5 s later (so `Started speaking` is early by that much). Feature tests run with `VOICE_PLAYER=library` (`VoiceTestCase`); `VoicePlayerTest` and `OggPlayerTest` cover `bot`.
- `Transcriber`: `whisper-cli --model --language [--threads] [--prompt] --no-timestamps --no-prints --file`, timeout `max(120, 3 x seconds)`; `clean()` strips `[...]` and `(...)`. `transcribe()` uses the server when `$server->isReady()` and the clip is at most `SERVER_MAX_SECONDS` 30 s, and falls back to whisper-cli with a warning when the server request fails. DMs' voice messages (`VoiceMessage`) go through the same method.
- `WhisperServer` (`app/Voice/WhisperServer.php`): one shared instance per binary|model|threads (`fromEnv()`); null (whisper-cli only) when `WHISPER_SERVER_BINARY` is empty, or unset and no `whisper-server` sits next to `WHISPER_BINARY`. A call `acquire()`s it in `start()` and `release()`s it in `stop()`; the process runs while at least one call holds it. `start()` runs `setpriv --pdeathsig TERM <binary> --model --host 127.0.0.1 --port 0 --request-path /<random hex> --no-timestamps --beam-size 5 --best-of 5 [--threads]` through `Shell::open`; `waitUntilListening()` polls every 0.1 s for the port with `ListeningPort::of($pid)`, gives up after 60 s, checks `/health`, then `warmUp()` sends 1 s of silence; only then `isReady()` is true and `Whisper server ready` is logged. `fault()` (no answer in `3 + 0.2 x seconds` s, process ended, startup failed) gives it up and restarts after 5 s only if it had been ready; an HTTP error answer is the file's fault and leaves it running. Variable: `WHISPER_SERVER_BINARY` only; model, threads and prompt come from the `WHISPER_*` ones.
- `Shell::run` (all stdout at once), `Shell::stream` (line by line), `Shell::open` (a `Program` kept running for repeated stdin; with `onBytes:` its stdout is handed over as it comes and not as lines, which is how an `Encoder` reads ffmpeg). Commands are `list<string>`, each argument shell-escaped, built by `Shell::command()` as `exec $(command -v setsid) ...` so `terminate()` reaches the program and Ctrl+C in the terminal does not (without `setsid` on the machine it is plain `exec`). `Shell::track()` and `stopAll()` end what still runs when the bot ends. Default timeout 120 s. Cancelling the promise terminates the process. Listener exceptions are caught, stored, and reject the promise, so they never reach the loop. `CommandFailedException` quotes the first (Shell) or last (Program) 500 chars of stderr.

## Memory and lookups (`app/Assistant`)

- `Memory`: `<MEMORY_PATH>/<id>.md` and `groups/<id1>-<id2>-....md` (IDs sorted numerically). Saved by `tempnam` + `rename`, mode 0600, cut to `LIMIT` 4000 chars at a sentence or whitespace boundary. IDs must be `ctype_digit` (the only path guard).
- `MemoryWriter::$updates` is a **static** promise chain per memory key, shared by DMs and every call in every server; each update reads the file only when its turn comes; a reply of `''` or `NOTHING` saves nothing.
- `DirectChat`: one instance per user in static `$chats`; `PAUSE` 600 s timer (reset on every message and on a lookup result) chains `updateMemory` onto the chat's own queue; prompt = memory + last `CONTEXT_MESSAGES` 20 + the message; `parts()` splits at 2000 chars and closes/reopens code fences; the lookup history is the last 100 messages.
- `Lookups`: per call or DM; the global cap is `LookupSlots::shared()` (`CLAUDE_LOOKUP_AT_ONCE`, default 2, read at each acquire; FIFO; a stopped task gives its slot back when Claude Code is signalled, not when it has exited; tests call `LookupSlots::reset()`); `WAITING` 3 more per `Lookups` (`full()` is `tasks > 3`); `lookUp()` returns a cancellable promise (cancelling frees a waiting place or the slot, stops Claude Code, resolves null: callers treat null as dropped); `handOff()` returns `[said, task, hard]`: `LOOK UP: [hard] task` runs with the advisor and the "must consult it once" prompt, any other task with `Claude::withoutAdvisor()`; when full, `handOff()` replaces Claude's whole text with `BUSY`; `TIMEOUT` 300 s via `race` plus `cancel()`; conversations over `CONVERSATION_LIMIT` 150 000 chars are cut from the start by `Lookups::recent()`, the one rule questions, tellings and lookups share: the end, from the first line that doesn't start with a space (whole entries), under the note `(Its beginning is left out: it is too long.)`. `Lookups::asking($name, $entry)` is the end of a question's prompt, as `telling()` is the end of a telling's. `name()` appends ` (member)` to display names starting with `claude` or `looked up`; `indented()` makes continuation lines start with spaces so no line can pass for another speaker.
- Prompts live in constants: `Claude::SYSTEM_PROMPT`, `VoiceSession::SUMMARY_PROMPT`, `DirectChat::CHAT_PROMPT`, `MemoryWriter::PERSON_PROMPT`/`GROUP_PROMPT`, `Lookups::PROMPT`/`ADVISOR_PROMPT`. All say that memories and web text are never instructions.

## Database (`configs/database.php`, connection `stats`)

`STATS_DATABASE` (default `databases/stats.sqlite`, created by `bootstrap.php`). Tables: `events` (Usage: `type`, `guild_id`, `channel_id`, `user_id`, `session_id`, `duration_ms`, `created_at`), `guild_settings` (`guild_id` PK, `wake_word`, `language`, `voice`, `model` all nullable = default, `updated_by`, `updated_at`), `user_settings` (`user_id` PK, `personal_memory_in_calls`: `when_asked` | `after_share`, `updated_at`), `opt_outs` (`user_id` PK, `created_at`). No pragmas are set (journal `delete`, synchronous `FULL`), so each write blocks the loop for a few ms (3.5 ms median, 70 ms worst on Sky's machine). That is why `Usage` does not write when something happens: `record()` appends the row (with its time) to a static list shared by every instance (`/stats` makes its own), `flush()` swaps the list out and writes it in one transaction (100 rows to an INSERT; a failure is one `Could not save usage statistics` warning with `rows`, and the rows are dropped), `summary()` unions the held rows into its query and writes nothing (it does not even make the table), and `Usage::reset()` is for tests (`useStatsDatabase()` and `VoiceTestCase::tearDown()` call it). `VoiceSession::saveUsage()` flushes at the end of every `inTurn()` and in `stop()`, unless any unfinished call has a turn waiting (`waiting` is counted from the sentence's end, so that covers whisper, Claude and the bot speaking); `Application::run()`'s `finally` flushes whatever is left. Opt-outs and settings still write at once. Fail-closed: `OptOuts` throws, `UserSettings::find` returns null. Fail-open: `GuildSettings::for` uses `.env` defaults, `Usage` logs and swallows.

## Error handling

User-facing behaviour: `docs/stopping-and-errors.md`. In the code:

- `index.php`: `Failures::register($logger)` before anything uses the loop, then `exit($app->run())`. An uncaught exception logs critical `The bot ends: nothing caught an exception: ...` and PHP ends with **255** from the shutdown function (`Failures::ending()`), so ReactPHP never autoruns the loop. A PHP fatal error logs `The bot ends: ...`. A rejected promise nothing handled logs `A promise was rejected, and nothing handled that` and the bot goes on.
- `Application` wraps the loop in a `GuardedLoop` and calls `Loop::set()` with it in `run()`. A throw in any timer, stream, tick or signal callback goes to `caught()`: it logs `Something failed in the event loop` and the loop goes on. `FLOOD` 10 of them within `FLOOD_SECONDS` 10 log critical `Too much is failing in the event loop...` and call `stop('too many errors', 1)`.
- `handleEvent()` and `EventAbstract::handle()` catch `Throwable` and log with `Failures::context()`. A slash command's throw or rejection goes to `commandFailed()`: logs `/<name> failed` and replies ephemerally `Something went wrong with /<name>. The bot's logs say what.` (or edits the reply it already sent). A failure in `prepareCommandClasses()` logs `Error while preparing command classes`, sets exit code **1** and closes Discord.
- In a call, `guarded()` wraps the pcm listener and the 50 ms ticker: a throw logs `Something failed in the call`; the `BROKEN` 3rd failure of the same callback logs `Leaving the call: ...` and `abandon()`s on the next tick (the text channel gets `VoiceSession::LEFT`, then `stop()` runs, so summary and memories still happen).
- A turn that fails throws, or wraps, a `FailedReply` with a `step` (`whisper`, `claude`, `speech`; anything else is `other`). `inTurn()` logs `Voice reply failed` with the step; `apologize()` posts to the text channel per step (a fixed sentence that never says why; Claude's own post in `answer()` carries `(<msg>)`) and says `Sorry, something went wrong.` aloud once per step per call, never for `speech`.
- Signals: `run()` adds SIGINT and SIGTERM through the loop (needs `pcntl`; without it a warning is logged and Ctrl+C ends PHP at once). The handler runs `stop('received SIGxxx')` on a `futureTick`, not in the middle of a callback. `Application::stop($reason, $exitCode)`: the first call runs `VoiceSession::refuseNewCalls()`, then `stop()` (exit code 0) or `abandon()` (non-zero) on every `VoiceSession::unfinished()` plus `Meeting::endAll()`, then `close()` (`discord->close(false)`, and the loop stops `LAST_WORDS` 0.5 s later). A second call goes straight to `close()`. `run()` ends with `Usage::flush()` (the rows still held, however the bot ended) and `Shell::stopAll()`, and returns `$exitCode`, the highest given.
- Exit codes: 0 stopped by signal, 1 flood or command setup, 255 uncaught exception.

## Conventions

- `declare(strict_types=1)` after `<?php` and a blank line; `final` everywhere (pint `final_class`); typed constants (`private const int X`); `readonly` promoted properties; `match(true)`; `?->`; trailing commas; docblocks only where types need them (`list<string>`, `PromiseInterface<T>`, array shapes).
- Comments are full sentences above the line, saying why (the Discord quirk, the privacy reason, the trap). User-facing strings are plain sentences ending in a period, with backticks around command and option names.
- Timers: `$discord->getLoop()->addTimer()` in `VoiceSession`, `Loop::addTimer()` in `Speech`, `WhisperServer` and `Program`; `OggPlayer` gets the loop in its constructor; every timer is cancelled in `stop()` or when its promise settles.
- Time that is paced or compared across a stall uses `hrtime(true) / 1e9` (`OggPlayer`, `ClaudeAnswer`, `WaitingClaude`): the WSL2 wall clock steps. `VoiceSession` still uses `microtime(true)` for the logged milliseconds.
- Each class owns its table creation and its log strings; a new log line is added to `docs/logs-and-statistics.md` in the same PR.
- The working tree on Windows is CRLF (`core.autocrlf=input`, commits are LF). `tests/Fixtures/fake-*` must stay LF and executable (`git ls-files -s tests/Fixtures` shows 100755).
