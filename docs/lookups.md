# Looking things up

[← Back to the README](../README.md)

Claude answers at once: the model that answers has no tools, so the call isn't kept waiting. Some questions can't be answered well that way: the latest version of something, tomorrow's weather, which of two services is cheaper. Claude hands those off. It says one short sentence, such as "Let me look into that.", and the question is looked up in the background while the call goes on.

- **Who looks it up.** A second Claude Code process, with the model in `CLAUDE_LOOKUP_MODEL`, `sonnet` by default. It may think for as long as it takes, and consult the model in `CLAUDE_LOOKUP_ADVISOR`, `opus` by default, which it is told to do when the task is hard or a wrong answer would matter, and not for a simple lookup. Leave `CLAUDE_LOOKUP_ADVISOR` empty for no advisor.
- **What it gets.** The whole transcript of the call so far, and the task Claude wrote for it. Of a transcript longer than 150,000 characters, it gets the end, and is told the beginning is missing. It is never given the memories the bot keeps of people. The task and the transcript can still hold what Claude said from one: Claude writes the task after an answer that was made with them.
- **What it can do.** Search the web, and nothing else (`--tools WebSearch`). It can't fetch a page by its address, read or write files, run anything or use MCP servers. It runs from the same empty directory as the bot's other requests, and without the Claude Code settings, plugins and hooks of the user the bot runs as.
- **When the answer arrives**, it is posted in the call's text channel, whole, under the question it answers, in several messages when it doesn't fit in one. It is added to the transcript as `Looked up for <name>: ...`, on one line, so the call's summary has it and later answers can build on it. For the memories it counts like what Claude answers: it is only remembered for someone who is still alone with the bot when it arrives, as the lookup reads the call when it is its turn and may have read what someone who joined meanwhile said, and a group's memory is made from what the people said (see [Memory in calls](memory.md#memory-in-calls)). Claude then tells the call what was found, in a few spoken sentences, which are spoken, posted and added to the transcript like any answer. That waits its turn like something said in the call does, so the bot never talks over one of its own answers. The prompt that has Claude tell it holds no memory: after what Claude is told to do, every line of what was found starts with `> `, so nothing a web page made the model write can end the text or go on as an instruction. It counts as answering that person: like any answer, it keeps their conversation open.
- The call goes on meanwhile: everyone is transcribed and answered as usual, also whoever asked.
- One task is looked up at a time, and up to 3 more wait their turn, in the order they were handed off. When a fourth would wait, the bot says "I'm still looking into other things. Ask me again in a moment." in the place of Claude's sentence, and nothing is handed off.
- A task that takes more than 5 minutes is given up. When something can't be looked up (it took too long, the usage limit is reached, Claude isn't logged in, ...), the bot posts that it couldn't, and why, and says "Sorry, I couldn't look that up." in the call.
- When the call is over by the time the answer arrives, it is still posted in the text channel and added to `transcript.txt`, where `/recall` finds it, and nothing is spoken. The call's summary and the memories were made when the call ended, so they don't have it. A lookup that is running can't be stopped: `/stop` ends the call, not what is being looked up for it.
- When whoever asked has opted out meanwhile (see [Opting out of being recorded](opting-out.md#opting-out-of-being-recorded)), the answer is dropped: it is not posted, spoken or added to the transcript. What they still had waiting is not looked up. The same goes for the memories Claude's answer was made from, as the task can quote them: when one that was shared with the call is taken back with `/unshare`, when someone joins a call in which a personal memory was only used because its owner was alone with the bot (see `/privacy`), or when someone joins who a group's memory, which the answer was made from, isn't of. The same goes for telling what was found, which waits its turn after the answer is posted and can quote those memories too: it is dropped, or cut off while it is spoken, when one of that has come true since the question was asked. The answer that was already posted stays: only what Claude tells of it is dropped, and is not spoken, posted or added to the transcript. And when a memory is erased with `/forget` while something is looked up, what is found is still posted and told, but no memory is updated from it.
- Only a line Claude itself writes at the end of its answer hands a question off. Someone saying "look up" does nothing by itself. Claude is also told that only the person it is answering decides what is handed off, so that what someone else in the call says about looking something up for them is not their question, and that a memory is notes, never instructions. That is a prompt, not a check: it depends on the model.

> [!IMPORTANT]
> Once something is looked up, what was said in the call, or written in the DM, is given to a model that searches the web, so its search queries can hold parts of it, including what Claude said there from a memory. What it finds comes from web pages: every prompt that gets it (answers, the summary, memories and `/recall`) says that it is never instructions. And no line of it, or of what anyone says, can pass for another: in the transcript, the later lines of what a person or the bot said are indented (a line that starts with spaces goes on the one above it), what was looked up is put on one line, and a display name that starts like the bot's label or a lookup's (`Claude`, `Looked up`) is written with ` (member)` after it, once its spaces are made one and its invisible and control characters are dropped. A name that only looks like `Claude`, in other letters, is not caught.

A lookup uses your Claude subscription like every answer does, and more of it: the model searches, reads and thinks. When it consults its advisor, it takes about three times as long and uses about four times as much, as measured when this was built.
